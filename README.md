# WorkTool 本地项目工作台

个人项目与应用包管理桌面客户端。采用 Electron，支持 Mac / Windows 构建。此交付使用独立示例资料，不含公司数据和凭据。

## 在这台 Mac 上试用

最新应用位于 `dist/validated/mac-arm64/WorkTool.app`，同版本构建保存在 `dist/detail-ui-20261123/mac-arm64/WorkTool.app`，新增紧凑任务清单、进度概览和页内搜索高亮，包含应用 Icon、Markdown 文档阅读、跳板机入口、共享项目知识库及资料导入。本轮升级前的版本保留在 `dist/validated-before-detail-ui-20261123/`。本轮更新的是项目内运行包。

先用默认示例资料体验，再到「Git 同步 → 选择工作区」选择独立空目录。不要把源码目录选作资料工作区。应用数据与代码是两套独立目录；关闭客户端后数据仍保留。Mac 默认资料位于 `~/Library/Application Support/WorkTool/workspace`，Windows 默认位于 `%APPDATA%/WorkTool/workspace`；选过其他工作区后使用所选目录。

可以先创建项目，再录入应用名、包名、分支、flavor 和跳板机 VPS IP 地址；进入包详情从模板添加任务，填写配置内容或关联文档。模板的新增、删除、改名与排序不影响已生成的任务。知识文档支持关联项目，也可保存通用知识。

跳板机 VPS IP 位于「应用基本配置」，填写通过 Windows App 连接的 IP 地址，支持 IPv4 / IPv6、可留空，不含端口。应用列表、搜索和导入预览均支持此字段；可使用下方跳板机卡片查询平台状态及手动开机。旧版账号数据保留在本地工作区以兼容已有资料，界面不再提供 GP 账号栏。


## 详情页与任务进度

项目、应用和文档详情页的返回按钮位于固定顶栏。应用任务以紧凑行显示标题、内容摘要和完成状态，点击「展开」查看完整内容、备注及附件；任务清单上方显示百分比、已完成及待完成数量，勾选后同步更新。

详情页顶部搜索框只查找当前页内容，按 ⌘F / Ctrl+F 可快速聚焦。匹配文本会高亮，当前项使用更深的颜色；Enter / Shift+Enter 或上下箭头切换匹配，Esc 清除。命中折叠任务的内容时自动展开，清除搜索后恢复原来的展开状态。搜索不会改动或保存资料，也不会发送网络请求。项目和包名列表继续使用全局筛选。

## 应用 Icon

在「编辑应用配置」或新建应用时，点击「选择图标」选择本地 PNG / JPG / JPEG，支持预览、更换和移除。选择后点击「保存」才生效；取消不会改动原图标。图片限 10 MB、宽高 16–4096 像素，会按比例生成最长边 512px 的 PNG，保留透明背景。

Icon 显示在工作概览、项目详情、包名列表的应用名称左侧，以及应用详情标题旁。未设置或文件不可用时显示名称首字。图标使用工作区内的相对附件路径，重启或移动整个工作区后仍可读取；移除或更换不删除旧文件，以保留已有备份和引用。连接知识库后，应用 Markdown 和图标附件会一并导出。

## Markdown 文档阅读

「知识文档」详情按 Markdown 排版，支持标题、粗体/斜体/删除线、有序和无序列表、嵌套列表、只读任务列表、引用、分隔线、表格、行内代码及代码块。长代码和宽表格在内容区域内横向滚动。

点击网页链接用系统浏览器打开，文内标题链接跳转到对应段落；本机绝对路径或已关联附件链接在 Finder / 文件管理器中定位。其他电脑上的路径或未关联的相对路径会提示无法找到。图片语法显示为可点击的图片链接，不自动加载远端图片。原文中的 HTML 作为文字显示。

「编辑文档」仍编辑 Markdown 原文；阅读不改变正文、原始附件或 Git 导出的 Markdown 文件。

## 跳板机状态与开机

在应用详情的「应用基本配置」中填写 VPS IP 后，可使用跳板机卡片：

1. 首次点击「登录管理平台」，在 WorkTool 打开的 UserCenter 窗口中登录。该窗口与 Safari / Chrome 的登录状态独立；关闭窗口后可返回工作台。
2. 每次进入应用详情页时查询一次平台状态；停留页面或切回窗口不会继续查询，需要更新时点击「刷新状态」。显示平台记录的已开机、已关机、开机中等状态及查询时间，不代表远程桌面已连接。
3. 已关机时点击「一键开机」。程序会先核对精确 IP、唯一主机记录及最新版本，再提交一次开机请求并回查一次状态；后续可手动刷新查看进度。超时或失败会明确提示；不会自动重试开机，也不会自动开机抵消平台的每日关机安排。
4. 「打开管理平台」进入 `https://uc.ushareit.org/index.html?#/bastion-host`，自动填写当前应用 IP 并查询，便于查看详情或操作日志。登录凭证过期时自动调用平台续期接口；如需密码兜底，可在「平台自动登录」保存并验证账号密码。密码使用本机 AES-GCM 密钥加密，凭据和密钥文件以 0600 权限保存在本机 userData，不访问钥匙串或 Electron safeStorage，不随项目同步；验证失败后暂停自动密码登录，更新密码后恢复。未保存密码仍可续期现有会话。
5. 「连接跳板机」会重新核对当前 IP 的开机状态，通过 Windows App 官方 CLI 只读匹配已有连接，再打开该连接以复用客户端保存的密码。首次需要在 macOS 辅助功能设置中允许 WorkTool；未授权时会打开 Windows App 并给出设置入口，也可直接手动点击已有连接。未找到已保存连接时通过不含密码的 `.rdp` 文件打开该 IP。重复匹配或未找到可见卡片会停止，不猜测目标。平台账号不会传给远程桌面，证书窗口由用户确认。
6. 登录恢复仅在详情查询、手动刷新或平台入口需要时触发；并发查询共用一次恢复。网络故障不反复提交密码，开机请求不自动重放。可在「平台自动登录」手动续期，或移除已保存的密码。


平台会话仅保留在本机 WorkTool 的独立浏览器数据中，不写入项目 JSON、导入资料、日志或知识库。WorkTool 不提供关机按钮，也不更改定时策略。Windows App 内的远程桌面账号由客户端管理。

## 共享项目知识库

项目表单中的原「代码仓库地址」改为「项目知识库 Git 仓库地址」。所有项目共用一个知识库仓库，填一次后新建项目和导入资料自动继承；旧代码仓库值不会自动迁移成知识库目标。

1. 在新建/编辑项目，或「Git 同步 → 设置知识库地址」中填写现有仓库的 HTTPS / SSH Git 地址。
2. 点击「连接并写入本地仓库」。应用在 userData 的 `knowledge-repositories/` 下克隆仓库，并写入当前项目资料；访问权限沿用本机 Git 配置，不会新建远端仓库。
3. 连接后，新增、编辑或导入文档以及更新项目配置，会自动更新本地知识库。每个项目位于 `worktool/projects/<项目名>-<稳定标识>/`，包含 `README.md`、`docs/`、`applications/` 和 `attachments/`；通用知识位于 `worktool/general/`。同名项目也使用独立目录。正文为可读 Markdown，原始图片和文件按原字节复制。
4. 点击「提交并同步知识库」，审核过的资料会生成 Git 提交并推送当前分支。保存本地文档不会自动推送。

遇到外部编辑、远端文档变化、分叉或其他工作区的已有资料时停止覆盖，并在界面显示原因。应用中的新内容仍保留，可先在 Git 工具中核对。外部 Markdown 不会自动导入覆盖应用数据；`hub.json` 继续负责应用索引和本地恢复。知识库不包含 API Key、`hub.json` 或工作区备份；仓库中的其他手写资料保留。

## 截图创建项目

在「新建项目」的虚线区域拖入图片或文档，也可按 ⌘V / Ctrl+V 粘贴截图；仍可点击「选择截图识别」或「粘贴截图识别」。一次处理一个文件。LongCat 会提取项目名称、项目说明，以及图中存在的应用名、包名、分支、Flavor 等字段。预览已自动填写这些内容，核对后勾选确认并保存即可创建项目；没有应用信息的截图也能单独创建项目。未出现的字段留空，唯一应用名可作为项目名称。截图和转写文字保存为项目文档，已有项目不会被覆盖。

## 导入项目资料

进入「导入资料」，可把文件直接拖入虚线区域、选择本地文件、按 ⌘V / Ctrl+V 粘贴截图，或在文本框粘贴钉钉表格、Markdown、配置文字。已有预览需要先保存或取消，再导入下一份。支持 MD / Markdown、TXT、CSV 文件和粘贴的 TSV 表格；截图支持 PNG / JPG / JPEG / WebP，WebP 使用无网络权限的隔离解码窗口转换。Mac 另支持 DOCX 文字提取。新导入入口不支持 PDF；Excel 请另存 CSV。

先到「AI 设置」填写 LongCat API Key，默认模型 `LongCat-2.5`，点击「保存并测试连接」。配置后导入默认选择 LongCat AI：截图直接发送给视觉模型，文字直接提取项目字段，关闭深度思考；DOCX 在 Mac 提取文字后再发送。普通截图保持完整，超过接口尺寸的图片会按原分辨率分块，最多 16 块。每次网络请求最多等待 60 秒，无自动重试；失败后可手动重试或改用本地识别。重新解析会再次调用 AI，确认保存不会再次调用。

API Key 按用户要求以明文保存在本机 userData 的 `ai-settings.json`，文件权限为 `0600`（仅当前用户读写），不使用系统钥匙串或 Electron safeStorage，不进入资料工作区；渲染页面只收到是否已配置的状态。Mac 默认路径为 `~/Library/Application Support/WorkTool/ai-settings.json`。旧的加密配置不会自动解密，需要重新填 Key。测试连接只发送简短测试文字。选择 LongCat AI 代表所选资料会上传到 LongCat，请提前移除截图里的敏感内容；文本在上传前经过既有常见凭据检查。

仍可选择「本地识别（离线）」：Mac 截图使用 Vision，DOCX 使用 textutil，文本使用规则解析。Windows 的 AI 文本/截图代码路径已接入，但没有 Windows 实机验收；DOCX 提取仍仅支持 Mac。

预览中选择已有项目或填写新项目名称，核对应用名、包名、分支、Flavor、跳板机 VPS IP 地址及配置项，再勾选确认并保存。要求 AI 对未提供的字段留空，但模型输出仍需核对；取消应用勾选可仅保存文档。一批资料统一归属一个项目，不同项目请分批。已有包名或同一原件会拦截重复导入，不会覆盖已有产品。

Markdown 正文保存在项目文档中，原始 `.md` / 截图 / DOCX 等文件会独立复制到附件，文档详情可打开原件。编辑正文不会修改原件。新项目说明会从 AI 结果自动填写并随确认保存；知识库地址继承当前共享配置，截图中的代码仓库不会自动成为知识库地址；选择已有项目时保留已有项目信息。原文件上限 20 MB，识别文字上限 1 MB，一次最多 100 个应用候选。

截图可能误识别字符或排版，请核对字段值。已兼容 Vision 将标签 `ApplicationId` 读成 `Applicationld` 的情况，仅匹配标签并提示核对，不修改包名值。DOCX 表格布局可能在提取时丢失。常见凭据拦截不等于完整扫描，原件中的隐藏内容也需核对。

验证包括 53 项后端测试、渲染逻辑检查、AI 桌面流程和既有功能回归，均使用隔离的合成资料。AI 测试采用模拟 HTTP 响应，API Key 的本地保存、重启读取、移除和文件权限均已验证，不访问钥匙串。2026-11-13 已用用户配置完成真实 LongCat 连接测试（约 2.2 秒）及一份合成文字资料提取（约 3.4 秒）；已补齐中文标签到结构化字段的映射提示。另有两张合成截图通过真实接口提取和自动创建验证（约 4.1 秒 / 6.7 秒），PNG/JPG/JPEG/WebP 解码均通过。本次修复了 Electron 剪贴板接口变更导致的粘贴报错，已验证真实系统剪贴板、⌘V 和粘贴按钮，并用用户提供的表格截图进入 LongCat 预览。实测出现应用名大小写偏差，仍需核对后保存。详细证据见 `VALIDATION.md`。

## 开发运行

需要 Node.js 22+ 和 Git。进入源码目录：

```sh
npm ci
npm run setup:desktop
npm run build:native
npm test
npm run test:logic
npm run test:ai
npm start
```

Mac 打包：`npm run dist:mac`；Windows 在 Windows 上运行 `npm run dist:win`。
生成文件位于 `dist/`。未做 Apple 签名/公证或 Windows 代码签名。请勿绕过系统安全警告。

`setup:desktop` 安装锁定版本的 Electron 运行时，仅第一次需要下载。依赖仅安装到项目，不需要全局安装。`npm run test:desktop` 使用真实 Electron 窗口和临时合成工作区运行回归，报告位于 `validation/desktop-results.json`。该测试替代了云端硬编码 Linux 路径的 `renderer/ui-test.cjs`；文件选择器在自动测试中返回合成文件路径，不代表原生对话框已经人工验收。

## 数据

首次启动在 Electron userData 的 workspace 中创建演示 `hub.json`。可通过同步页面选择空目录或已有 WorkTool 工作区。源码与资料工作区建议分开。

资料格式：`hub.json`（项目/包/账号索引/模板/文档/任务），`attachments/`（导入文档），`.backups/`（每次保存前备份）。操作失败不自动重置损坏文件；启动时错误会明确显示。

文档正文保存在 hub.json；连接共享知识库后，同时输出独立 Markdown 文件。清单完成状态与填写内容独立；模板生成清单后互不影响。导入的附件随工作区移动，删除关联不会立即销毁磁盘文件。

## Git 同步边界

「工作区 Git 备份」沿用原流程，对完整应用资料工作区检查状态、fetch、仅快进合并与 push；此入口不会自动提交。它与上面的「共享项目知识库」分开，后者只在明确点击「提交并同步」时提交生成的项目资料。两者均不强制推送或自动解决冲突。请先使用已有 Git 工具初始化资料目录、设置远端与 upstream，并审核提交。应用同步会要求再次确认。

远端可以是公司 Git、GitHub、GitLab。使用现有 Git 认证环境，不收集凭据；认证失效时在自己的 Git 工具中处理。无需公司仓库也能使用全部本地管理功能。

**请排除 `.backups/`，禁止提交密码、签名密钥、服务账号私钥、API secrets 或不允许外传的公司资料。** 原任务附件入口支持 md/txt/pdf/png/jpg/jpeg/webp/csv，最多 20 MB；与上面的「导入资料」入口不同，原附件入口保留 PDF。文件内容仍需自行确认无敏感信息。支持普通配置标识不是授权同步秘密。

同步前需要干净的提交工作区，远端分叉时停止。版本冲突保护可阻止过期窗口覆盖较新保存。每日/重大修改后仍建议保留独立备份。

## 已知初版边界

没有团队登录、Google Play API、远端自动建仓、通用秘密管理、后台自动提交、冲突解决器、数据自动迁移和 AI 问答；AI 目前仅用于资料导入。Mac/Windows 本地代码路径尚未实现。Markdown 使用原文编辑器，阅读页显示排版后的内容，不执行原文中的 HTML。完整测试记录见 VALIDATION.md。

当前任务挂在应用包下，项目级独立待办尚未实现；首页能按产品名称、包名、分支、flavor、账号查找项目和应用包，各其他页面主要筛选当前列表。账户卡片暂不直接展开关联包清单。应用文档索引保存在 `hub.json`，连接知识库后会自动导出各项目的独立 Markdown 文档；导入资料的 Markdown 原件已可独立保留并从文档详情打开。

已验证范围为本机 Apple Silicon Mac。Windows 保留构建配置，但没有完成 Windows 打包与实机启动验证；公司 Git、GitHub/GitLab 私有仓库的实际认证均未连接测试。本次测试只使用本地临时仓库，没有推送网络远端。

管理平台自动登录的本机文件是 `bastion-auth.json` 和 `bastion-auth.json.key`，都位于 userData，权限均为 0600。该本机加密用于避免配置文件直接出现明文密码，不能阻止当前用户权限的其他程序同时读取密钥和密文。旧钥匙串格式只提示重新保存，不自动解密或访问钥匙串。
